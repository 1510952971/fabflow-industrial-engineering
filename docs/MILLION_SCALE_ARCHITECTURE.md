# 百万级设备材料型录数据架构与压测说明

## 目标与边界

- 支持至少 1,000,000 条产品主记录，以及产品规格、适用系统、介质、材质、认证、标准等关联记录。
- PDF、图片、Excel/CSV 原件存入 R2；D1 只保存可查询的结构化元数据、对象键、版本、哈希和业务关系，禁止把二进制文件写入 D1 BLOB。
- 前端任何页面一次最多读取 60～200 条数据，使用游标翻页；禁止把全库数据下载到浏览器后筛选。
- 自动选型先执行有索引的数据库预筛，再对最多 2,000 个候选执行详细工程规则；条件过宽时要求用户补充分类、系统、介质或工况。
- 产品编辑内容停止输入 800ms 后写入当前用户的 D1 草稿，正式保存后清除草稿；关闭浏览器或程序后可恢复未提交内容。

## 数据分层

| 数据 | 存储 | 说明 |
|---|---|---|
| 产品、型号、规格、系统、Tag、接口、BOM | D1 | 强关系、索引查询、审批和版本引用 |
| 系统/介质/材质/认证/标准检索维度 | D1 `catalog_product_facets` | 规范化值并建立复合索引，避免扫描 JSON |
| 编辑草稿 | D1 `user_drafts` | 每用户隔离，单草稿上限 512KB，不存附件 |
| PDF、图片、表格原件 | R2 | D1 的 `attachments` 只存对象键、SHA-256、版本和元数据 |
| OCR/表格解析结果 | D1 元数据 + R2 中间文件 | 通过后台任务分批处理，不阻塞上传请求 |
| 审计和历史版本 | D1，按保留期归档 | 与在线业务表分离增长，避免无限膨胀 |

## 查询和写入规则

1. 列表使用 `(category_id, updated_at, id)` 或 `(updated_at, id)` 键集游标，不使用深页 `OFFSET`。
2. 高频过滤字段使用复合索引；系统、介质、材质等多值字段同步写入 facet 表。
3. `%关键词%` 模糊查询不得作为百万级主入口；生产环境应接 D1 FTS/外部搜索服务，或要求分类/品牌前缀后再搜。
4. Excel/CSV 导入按 500～2,000 行切片，包含幂等键、断点游标、失败重试和死信记录；每批提交后立即释放内存。
5. 文件上传应直传 R2。当前 25MB 单请求适合常规模型资料；更大的 PDF/表格应使用 R2 multipart upload，不经过应用进程整文件缓存。
6. 所有接口设置候选数、页大小、草稿大小和附件大小上限，避免单个请求拖垮 Worker。

## 本机正式压测结果（2026-07-21）

命令：`npm run benchmark:catalog`

- 产品主记录：1,000,000 条
- 系统/介质索引记录：2,000,000 条
- 总行数：3,000,000 条
- 写入时间：124.49 秒（约 8,033 个产品/秒，同时维护全部索引）
- 数据库体积：670.58 MiB
- 游标翻页 P50 / P95 / Max：0.096 / 0.252 / 0.720 ms
- 工程筛选 P50 / P95 / Max：20.90 / 35.97 / 164.43 ms
- Node 进程峰值 RSS：117.23 MiB
- 结果：通过；无闪退、无内存失控，查询计划命中覆盖索引。

压测数据库位于 `work/benchmarks/`，被视为临时数据，不得上传 Git，也不进入正式型录库。

## Cloudflare 容量规划

Cloudflare D1 当前付费计划单库最大 10GB，免费计划单库最大 500MB，而且单个 D1 数据库按顺序执行查询。上述合成数据约 671MB，但真实产品的动态规格、版本和审计通常更大，因此不能简单认定“100 万真实产品一定能放进同一个 D1”。

生产规则：

- 预计单库超过 6GB 或持续高写入时，提前按租户/目录域/归档年份拆分 D1；留出索引重建、迁移和 Time Travel 空间。
- 全球共享产品主索引保留轻量字段，详细规格和历史版本按目录分片；对象文件始终放 R2。
- 如果必须对百万产品执行复杂任意组合、JSON 条件和全文检索，建议把产品检索主库升级为托管 PostgreSQL（通过 Hyperdrive），D1 保留项目边缘数据和工作流。
- 监控 D1 查询读取行数、P95/P99 延迟、数据库大小、失败率和队列积压；达到 70% 容量或 P95 超过 250ms 时触发扩容/分片预警。

官方限制参考：

- https://developers.cloudflare.com/d1/platform/limits/
- https://developers.cloudflare.com/d1/best-practices/use-indexes/
- https://developers.cloudflare.com/r2/platform/limits/
- https://developers.cloudflare.com/r2/objects/upload-objects/

## 程序启动与停止

本地开发使用 `npm run dev` 前台运行，不安装 Windows 服务，也不启动独立常驻导入进程。按 `Ctrl+C` 或关闭运行终端后，HTTP 服务和当前解析任务停止；已提交到 D1/R2 的数据不会丢失，未完成编辑由 `user_drafts` 恢复。生产导入任务应放入有显式状态的队列，不能依赖浏览器页面持续打开。
