# Facility Construction Management Software 操作说明

本文适用于本地开发版和部署后的 Facility Construction Management Software 厂务工程与设备材料选型系统。系统遵循“全局型录共享、项目条件隔离、选型结果引用、校验证据留痕”的数据原则。

## 1. 首次安装与启动

环境要求：Windows 10/11，Node.js 22.13 或更高版本。

```powershell
cd "C:\Users\TCS\Documents\设备材料选型"
npm install
npm run db:migrate:local
npm run dev
```

打开终端显示的 `Local` 地址。默认是 `http://localhost:3000`；端口被占用时必须使用终端实际显示的地址，不要继续打开旧端口。

首次运行时点击右上角“账号登录”→“初始化系统管理员”，填写姓名、邮箱和至少 10 位且同时包含字母、数字的密码。管理员可以在“数据底座与协同 → 权限与审批”创建用户、重置密码、停用账号并授予项目角色。

## 1.1 整个材料型录文件夹批量录入

本地需要一次性录入整个 `材料型录/` 文件夹时，先运行 `npm run catalog:manifest` 更新资料清单，再运行 `npm run catalog:import-preview` 核对预计数量，最后运行 `npm run catalog:import-local`。该命令会先在 `work/backups/` 备份本地 D1，然后登记全部来源文件、按“厂家 + 型号/配置”去重、建立产品草稿和系统适用性记录。自动生成的产品一律保持 `draft`，不会绕过技术审核成为批准产品；无法从文件名安全识别唯一型号的型录、表格和扫描件进入待复核队列。

产品草稿建立后运行 `npm run catalog:enrich-preview` 和 `npm run catalog:enrich-local`。正文解析会从关联 PDF 提取压力、温度、口径、连接、接液材质、表面处理、流量、电源、通讯、防护等级、危险区等级、认证、标准和分类专用参数，并保存来源页码与原文证据。没有文字层的扫描件标记为 `ocr_required`，不得用空值或推测值冒充样册参数；所有自动值仍需工程师复核后才能批准。

## 2. 五步设计与选型主流程

### 第一步：创建项目

1. 打开“项目工作台”，点击“新建项目”。
2. 填写项目编号、名称、国家/地区、Fab、设计阶段、编号前缀和采购余量。
3. 勾选项目需要的厂务系统。标准模板覆盖特气、大宗气、化学品、超纯水、纯废水、工艺排气、洁净包、动力、消防、机电和自控等工程域。
4. 点击“创建并进入项目”。系统会在 D1 建立项目、系统、项目权限边界和资料目录。
5. 确认浏览器地址为 `/projects/{projectId}/{module}`，后续所有项目数据都以该项目 ID 为范围。

### 第二步：上传并确认项目技术规格书

1. 进入“设计与选型 → 设备材料型录库”。全局型录不属于任何单一项目，项目只保存自己的规格条件和产品引用。
2. 在“项目技术规格选型”区域点击“新建选型要求”。
3. 填写需求编号、标题、系统、产品分类和规格书版本，并上传 PDF、文本、Word、Excel、图片等资料。
4. PDF/文本会自动提取介质、设计压力、设计温度、公称尺寸、连接标准、允许材质、标准、认证和品牌要求。Word/Excel 当前保存原件并要求人工确认关键字段。
5. 核对高亮字段，修正识别错误后保存。未关联原件或未人工确认的要求不能进入正式选型。

### 第三步：匹配全局型录

1. 选择已确认的项目选型要求，点击运行匹配。
2. 系统逐项比较分类、适用系统、介质、压力、温度、尺寸、接口、材质、品牌、标准、认证和分类专用参数。
3. 查看每个候选的分数和问题：`通过`可选用，`关注`需工程师判断，`阻断`禁止选入 BOM。
4. 点击“选入项目 BOM”保存产品引用、校验快照和追溯关系；不会复制全局产品主档。
5. 没有合格产品时点击“生成候选记录”，依次完成 RFQ、TQ 技术澄清、供应商资料、品牌报审和技术复核；只有具备权限的管理员才能将通过复核的候选转入全局型录。

### 第四步：工程校验与设备内部选型

1. 在“合规校验中心”检查项目的系统、Tag、接口、BOM、测试包和 Punch 联合问题。
2. 进入“设备工厂协同”，选择设备厂、设备型号和内部部件。
3. 录入或核对内部部件的功能、介质、允许材质、表面处理、连接标准、尺寸、压力、温度、洁净等级以及双层管/软管要求。
4. 点击“整机自动配材并校验”。系统保存每个内部部件的选择结果、规则明细、得分和阻断原因。
5. 上传设备内部 BOM、接口图/GA/Hook-up Matrix、材质证明、表面处理报告和 FAT/ITP 记录。
6. 有致命不符合项时禁止生成设备 BOM；全部阻断关闭后点击“生成设备内部 BOM”。

### 第五步：冻结、BOM 与发布

1. 项目产品选型完成后提交“选型冻结审批”。
2. 设备内部材料和文件证据完整后提交“设备内部 BOM 冻结审批”。
3. 在“BOM 成本报表”检查物料编码、名称、规格、数量、单位、价格、系统、来源和采购余量。
4. 处理材料替代、品牌偏差、MOC、开放 Punch 和缺失测试包。
5. 提交项目发布审批。服务端会重新检查技术规格书、选型状态、设备内部校验、冻结门禁和项目 BOM，不能只靠前端按钮绕过。

## 3. 全局型录维护

平台管理员在“设备材料型录库 → 录入产品”维护公司级产品主档，可录入产品图片、制造商、品牌、系列、型号、适用系统、介质、温度、压力、连接、接液材质、表面处理、洁净等级、电气参数、通信协议、认证、标准、来源文件、页码、版本、选配型号和分类专用参数。

新增产品前先维护“产品分类”和“规格字段”模板。型录数据全公司共享；修改主档会影响后续项目匹配，因此正式产品应经过技术复核和品牌准入审批。

本机 `材料型录/` 目录中的 PDF/图片属于资料源，不会自动上传 GitHub。需要在另一台电脑继续使用这些原件时，应通过受控文件存储、NAS 或 R2 单独迁移。

### 批量登记 Catalog 型录与材料送审资料

1. 将厂家型录、产品数据表、品牌参数表、BOM、材料送审文件和图纸放入 `材料型录/`。子目录结构可以自由组织。
2. 在项目根目录运行 `npm run catalog:manifest`。程序会增量扫描全部子目录，生成已被 Git 忽略的 `work/catalog-source-manifest.json`。
3. 使用平台管理员账号进入“设备材料型录库”，点击“资料批量导入”，选择该 JSON，再点击“登记到资料库”。
4. 程序按 PDF、Excel、CAD/PDG/PAG、图片、旧版 Office 和压缩包分类，并以“资料根目录 + 相对路径”生成稳定来源键，大小和修改时间作为来源元数据更新；重复导入不会重复造数据，也不会覆盖已经完成的解析和复核状态。
5. 能从文件名识别厂家和型号的单品资料会生成“待复核产品候选”。初筛通过后点击“带入产品录入”，补齐产品分类、适用系统、介质、压力、温度、尺寸、连接、材质、认证、来源页码和分类专用参数，再保存为草稿或提交审核。
6. 多产品厂家型录、扫描件和复杂表格会保留为待解析任务。只有经过解析和人工复核的型号才可转成正式产品；送审图纸、证书和照片只作为产品证据，不直接当作产品。

清单只登记元数据，不上传约 17GB 的原件。正式部署时，原始 PDF、图纸、照片和签字件应进入 R2 或受控 NAS；D1 保存来源索引、候选产品、解析状态、版本和审计记录。

## 4. 设备厂数据接入

设备厂可以通过界面、CSV 模板或正式 API 提交设备型号、内部部件、接口和证据文件。正式 API 接入前需确定地址、认证方式、字段映射、网络白名单、幂等键和失败重试策略。未配置真实连接器时，界面中的连接状态不会伪装为已接通。

## 5. 数据保存位置

- D1：项目、系统、Tag、接口、材料、型录、项目要求、选型记录、BOM、订单、测试包、Punch、审批、版本和审计。
- R2：规格书、图纸、计算书、ITP/FAT、照片、签字文件和竣工资料。
- `.wrangler/state`：仅本机开发数据，已被 Git 忽略。
- `drizzle/`：数据库结构和基础数据迁移，会上传 GitHub。

## 6. 换电脑使用

```powershell
git clone https://github.com/1510952971/fabflow-industrial-engineering.git
cd fabflow-industrial-engineering
npm install
npm run db:migrate:local
npm run dev
```

更新已有副本：

```powershell
git pull
npm install
npm run db:migrate:local
```

如果要迁移当前电脑已经录入的数据，不能只执行 Git；需要另外导出/迁移 D1 与 R2。账号密码、Secret 和 `.env` 必须在新电脑或新部署环境重新配置。

## 7. 常见问题

### 浏览器显示 `Cannot read properties of null (reading 'use')`

先关闭所有旧的 Facility Construction Management Software 开发服务，确认终端没有第二个 `vinext dev`，再重新运行 `npm run dev` 并打开终端实际显示的端口。旧服务占用 3000 时，新服务会自动改用 3001；继续访问旧的 3000 会看到旧错误页面。

### 数据录入按钮不可用

确认已经登录，并由管理员授予当前项目的写入角色。全局型录写入需要平台管理员权限；匿名用户只有脱敏演示数据读取权限。

### 刷新后数据消失

确认已执行 `npm run db:migrate:local`，并通过真实保存按钮写入 D1。纯筛选条件和未提交表单不会持久化。

### 上传文件后另一台电脑看不到

GitHub 只保存源码。文件原件位于本地 R2 模拟目录或正式 R2，需要单独迁移或使用同一个正式 Cloudflare 环境。
